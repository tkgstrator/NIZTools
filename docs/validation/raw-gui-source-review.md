Current `app.rs:375`, `384`, and `429` disclose: `読み取り中は入力が一時停止し、補正状態が既定値に戻ることがあります。` It appears in the read button tooltip, visible helper, and snapshot details. The helper is hidden only during active owned calibration, when `can_read_raw_thresholds` disables reading; there is no enabled-reader state that relies solely on a hidden disclosure. The wording allows for no observable difference when compensation already equals the configured/default state and avoids claiming zero runtime effects.

Source/metadata rejection also retains 11 frames (`controller.rs:476-482`), and Worker metadata rejection retains frames (`worker.rs:163-171`). This is evidence preservation; safe rejection already existed.

## Integration conclusions

- **Explicit read request and owned target.** `protocol.rs:34`, `96-100` add dedicated Command/Response types. `Controller::dispatch` captures the concrete attached target and a cloned source baseline only for this request (`controller.rs:131-155`). `can_read_raw_thresholds` requires live target identity and exact supported firmware (`219-225`) and inherits pending/calibration/close blocking. Worker rejects stale/replayed operation and generation, missing or changed target, unsupported baseline, or calibration ownership before backend entry (`worker.rs:72-83`, `111-155`). The new read is explicitly included in target matching, rather than treated like unbound List.
- **Command, target, generation, and baseline are checked again on completion.** Controller drops unrelated tickets (`401-403`), checks raw reply versus raw command (`410-433`), then verifies live/close state, pending target, current concrete target, snapshot identity/firmware, exact support, and captured baseline records against the current baseline (`441-458`). Successful snapshots retain target, connection generation, completed-read time, baseline, and source tag (`460-467`). Unexpected command replies and changed metadata/source do not install a snapshot; they detach live use and retain diagnostics. Tests cover stale/duplicate completions, wrong firmware/identity/path/current source/baseline/live state, wrong response command, and accessor revalidation.
- **Cache lifecycle prevents old or partial values from appearing as a new read.** A new raw read clears the cache before dispatch (`250-252`). New baseline read, device selection/reconciliation loss, file import, trial/calibration start, close, and error clear or invalidate the cached snapshot (`169`, `198`, `289`, `309`, `339`, `391`, `575`, `608`). The accessor independently verifies live state, generation, target, and captured baseline (`228-240`). Backend I/O or metadata failure invalidates Worker until explicit baseline read (`worker.rs:156-171`). GUI pending/error tests prove old values disappear, and an error returns the display to `未取得`; there is no partial table or manufactured zero.
- **Native read uses the retained Session; demo is explicitly simulated.** `NativeBackend::read_raw_thresholds` uses the existing Session and checks a retained baseline; on failure it drops the baseline/Session (`worker.rs:259-271`). It does not open a second reader, use another lock, or call calibration. Device-level passive failure hold and actual DC parsing remain the separate Device review's responsibility. Demo constructs mode-1 frames with deliberately synthetic flat-index values and parses them through `RawThresholds::from_reports`, returning `RawThresholdSource::Simulation` (`384-407`). GUI visibly labels these as simulation values (`app.rs:386-387`) and marks the source in details (`427`). Native source tagging is the constant Device branch, independent of the demo branch.
- **Selection only chooses a cached physical-key value.** `app.rs:365-368` calls the device snapshot's physical-position accessor; it does not use assignment output or assume raw flat index equals drawn slot. `412-418` preserves the existing 66-position selector and operation/modal/popup guards. Synthetic matrix tests show S/#32 = 14, A/#31 = 13, and =/#13 = 60 (`app_tests.rs:1239-1271`), providing useful nonlinear-mapping fixtures. Full mapping/parser correctness belongs to the separately reviewed Core/Device layer, not just those GUI examples.
- **Read execution is manual and pointer-only.** `app.rs:371-378` gates on fresh exact source, confirmation, current popup and frame-start popup, and uses `clicked_by(Primary)`. No automatic request is attached to key selection, Enter, theme change, InputTest, or list response. `app_tests.rs:1365-1393` preserves the original snapshot timestamp and uses a real operation-ticket sentinel around repeated key/Enter/theme/input navigation, proving no hidden dispatch. The source/modal/popup/close guard test (`1326-1361`) and Controller/Worker guards pass. Active owned calibration keeps its existing cancellation/status surface, blocks reading and selection, and does not revive Begin/Held/Finish UI controls.
- **Snapshot meaning is appropriately bounded.** Main text says `読み取り時の生しきい値`, formats decimal plus hex, and says normal-scan internal value / not mm (`app.rs:370`, `382`). Details include target, firmware, time/generation, Device versus DEMO source, frame count, and explicit no-continuous/no-other-mode measurement statements (`421-430`). This is a firmware threshold-table snapshot, not a depth gauge, live sensor stream, or qualification of every input mode. The unsupported per-key setter copy remains prominent (`363-364`); no slider, value setter, global Fn+7 card, or calibration write control was reintroduced.
- **Existing typography, viewport, hover, and input invariants pass.** The ordinary Body14 device-detail labels and firmware remain at `app.rs:684-693`, `904-917`, and confirmation firmware at `556`; rendered eight-row font checks, long-path containment, mixed-row centering, modal gates, and InputTest focus/activation behavior all pass.
