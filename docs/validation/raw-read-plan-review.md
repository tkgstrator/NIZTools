# Independent plan review: bounded raw actuation-table read

**Assessment: the mode-1-only read probe and subsequent manual snapshot feature are feasible with the gates below.** The recovered getter supports reading a firmware table; it does not support a selected-key setter, physical travel measurement, persistence verification, or continuous live ADC input. There is no reason to run any calibration/threshold-changing command for this request.

This is a Codex fallback independent review, not a LocalGPT/Claude Code MCP review. Native read access was verified on `devonlys-MacBook-Pro.local` at `/Users/devonly/Developer/personal/NIZ`. No repository source or Git changes, HID commands, native GUI actions, or tests of a not-yet-written implementation were performed. The only new file is this report. Static firmware claims below are attributed to the supplied exact-image reports; this review checks their application to the existing source rather than repeating disassembly.

## Material gates and risks

1. **P1 if omitted — narrow the existing transport gate before DC.** `transport.rs:11-16` accepts PID 502a, 512a, and 522a; `open` (`102-138`) checks supported identity, actual-open identity stability, and the report descriptor, but does not enforce the proposed exact 502a model. Both the isolated probe and public API must explicitly require VID 0483 / PID 502a / usage 008c:1 and the exact fresh F9 string `66EC(XRGB)BLe;V1.0.48;V1.0;` before DC. Use the observed exact path; capture and compare its product against the intended descriptor rather than silently using a different matching device. `open` does not return/revalidate the product string after open, so document whether product matching is a pre-open enumeration check or add a minimal actual-open product check if exact product stability is an acceptance condition. Fresh F9 plus exact actual identity are the critical command-safety gate; matching a GUI `Profile` alone is insufficient. Do not relax the pin based on a similar family/version prefix.

2. **P1 if omitted — invert the proven physical-number permutation; do not index by drawn slot.** The firmware report (`per-key-firmware-report.md:101`, `157-183`) and independent report (`firmware-independent-review.md:69-71`) establish that DC returns 11×6 matrix order and table 0x9dc6 maps that order to physical numbers 1..66. GUI `PHYSICAL_LEGENDS` (`keyboard.rs:77-144`) is already physical-number order. Therefore slot `k-1` must select the matrix cell for physical number `k`, not raw flat cell `k-1`. The CSV gives nontrivial fixtures: key 1→flat 0; key 7→29; key 12→24; key 13→60; A/key 31→13; S/key 32→14; Enter/key 42→64; Right/key 66→59. Freeze the permutation with exact-image provenance and verify all 66 unique physical IDs and all 66 unique flat indexes. Keep the mapping pure and centralized near the device snapshot type so UI and protocol do not independently invent mappings.

3. **P2 — “read-only” means no persistent threshold write, not zero runtime effects.** Exact DC temporarily pauses/resets scan/key-output state and restores its own scan/compensation state (`per-key-firmware-report.md:163`, `183`; independent report `69`). Avoid running while the user is physically holding a key where practical, and do not call it stateless or promise no transient typing effect. On timeout/disconnect, do not send D9, DB/DD, D5/D8, unlock/calibration cleanup, a setter, or any speculative recovery. Drop the owned host handle/lock, retain evidence, and report uncertainty about actual typing recovery. Native typing/visual verification belongs to Codex coordinator. A successful receive proves the table was returned; it does not itself prove every runtime state was restored or that persistent storage matches it.

4. **P2 — a standalone probe must respect the long-lived GUI Session lock.** `open` acquires the per-path lock before HID open (`transport.rs:102-105`), and `Native` owns it for the handle lifetime (`54-58`, `131-135`). `NativeBackend` retains `Session` after baseline read (`worker.rs:174-199`), so an already loaded GUI can legitimately make the isolated probe fail as busy. Busy is a safe stop. Do not use another lock directory, unlink the lock inode, open the same hardware through a different uncoordinated transport, kill a shared GUI/session, or bypass refusal. The formal API can use the already-owned native Session on the existing worker thread. `prepare` is a bounded zero-time queue drain (`transport.rs:64-76`); preserve it before F9 and again before DC, and fail without DC if draining fails.

5. **P2 — snapshot ownership and lifecycle need more than a raw array.** Bind the new request to the same captured concrete target and generation used for baseline ownership. `Controller::dispatch` currently includes target only for existing changing commands (`controller.rs:114-125`), and Worker target matching currently only covers those commands (`worker.rs:110-121`); a targeted read must be added explicitly to both cases. Worker must reject stale/replayed ticket, wrong target, absent fresh live baseline, active calibration, or poisoned Session. A `Response::RawThresholds` must be accepted only for the corresponding pending raw-read command, with matching snapshot firmware/identity/target/generation. Starting a new baseline generation, selecting/reconciling another device, loss/reconnect, reading/importing an offline source without a live target, application/calibration, or a raw-read error must clear or explicitly detach cached values. Do not combine new partial rows with an old successful snapshot. On failure, show no new values and no fabricated zero.

6. **P2 — qualify the displayed meaning.** DC mode 1 returns RAM R, the normal scan path's compensated-signal actuation threshold (`per-key-firmware-report.md:153`, `169`, `183`). It is not an instantaneous raw ADC sample and is not physical distance. The report also identifies an alternate scanner with baseline-derived 6/4 thresholds and explicitly leaves all-mode scanner qualification outside scope (`153`). Accordingly, “読み取り時のしきい値（生値）N” is reasonable snapshot copy if accompanied by the firmware-signal-unit / not-mm explanation; do not claim that N is the observed press depth or the active boundary in every operating mode. Do not label it current/live after external keyboard actions may have changed it. Keep the individual setter unsupported statement. Record the successful read time and identify the device/source in diagnostics.

## Approved bounded probe shape, conditional on tested code

- Select the observed exact path/descriptor, acquire the normal transport lock, validate the descriptor and exact actual identity, bounded-drain stale input, send one F9, require exactly 64 incoming bytes and the exact ASCII F9 firmware string, then bounded-drain again.
- Construct a 64-byte zero-filled payload with bytes 0..2 = `00 DC 01`, wrap it once as the existing HidApi 65-byte unnumbered output (`Session::send`, `session.rs:114-139`; `command`, `niz-core/protocol.rs:20-23`). Require output count 65. No alternate report-ID framing or shifted response normalization after failure.
- Read only the mode-1 stream: exactly 11 unique row numbers 1..11, 64 bytes per frame, header `00 DC`, byte 3 = 1, six values at bytes 4..9. Use one monotonic overall deadline and a bounded per-read timeout. The current `receive` (`session.rs:141-172`) fails a zero-byte read after at most 1 second even within the 30-second overall deadline; either preserve that deliberately or document the different bounded wait behavior. Waiting for bytes is distinct from resending a command; never resend F9/DC automatically.
- Permit out-of-order rows if row IDs map explicitly into the matrix; reject duplicate/missing/out-of-range rows, wrong prefix/opcode/mode, truncated/oversize input, I/O errors, short output, and deadline completion failure. Publish only a full 66-cell snapshot. Cell bytes are unsigned 0..255 raw values; do not invent a narrower “physical” range without additional evidence. Retain every received frame and opaque bytes 10..63, including nonzero tails, for success and failure diagnostics. Do not interpret these tails or require guessed zero padding.
- Do not request modes 0/2 or DF in this probe. DC mode 1 has no E6/F6 terminator; completion is the full set of 11 row IDs. The corrected mode-0 DF residual-tail layout (`per-key-firmware-report.md:173-181`) must not become a mode-1 parser requirement. After complete mode 1, release the handle/lock normally; no firmware unlock send is needed. A bounded zero-time queued-extra-frame check may capture unexpected residual input, but must not add an invented quiet-window protocol or wait for a nonexistent terminator.
- Retain the exact source/probe hash, host/path/product/identity/F9, outgoing bytes, incoming 11 raw frames, parsed matrix, mapped physical values, timings, and exit/error. The probe's explicit allowlist is F9 then one DC mode 1 only; a host `write` of these read requests is still HID I/O and must not be described as “no reports were sent.” No profile F2 read, setter, calibration, flash, or unknown opcode is needed for this first qualification.

## Minimal formal feature integration after a qualified probe

Use a small read-only snapshot type containing raw row-ordered cells, a physical-key accessor, firmware/identity, raw frames, and read time. Do not attach analog data to mutable output assignment records or make it a profile setting. A baseline-token signature such as `Session::read_raw_thresholds(&LiveBaseline)` fits existing `check_baseline` and `exact_target` (`session.rs:326-361`), followed by a fresh exact F9 before DC. Success need not invalidate the keymap baseline or increment Session generation; a failed I/O/parser transaction should follow the existing poison discipline (`106-112`) and require an explicit fresh connection/baseline. Never let this method run while `ready` reports calibration ownership (`88-104`).

Add a dedicated backend trait method, Command/Response variants, and Worker route. `NativeBackend` should use its retained Session/baseline; DemoBackend may provide deterministic clearly labeled demo values for tests, never values claimed to come from the hardware. Controller should gate on fresh live exact source and its existing `available`/target checks, preserve output editor/history on success, and associate the snapshot with the pending target/ticket. Existing list/editor/input paths must not dispatch raw reads implicitly.

In GUI, add one explicit manual `生値を読み取る` button to the unsupported threshold card. Clicking any of the 66 physical keys merely changes which successfully read cell is shown. Before reading, use `未取得`; while pending, show read progress and prevent overlapping reads; after failure, show the error without auto-retry. Keep `キーごとのしきい値変更は未対応です` prominent. A successful value line can be `読み取り時のしきい値（生値）: N` with `ファームウェアの信号値です。押し込み量や mm ではありません。` and a read timestamp. Avoid numeric input styling that suggests editability. Preserve current popup/modal/pending/close and active-cancel guards, fixed key geometry/hover behavior, 960×820 collapsed fit, 700×580 reachability, Body14 device-detail rows, and existing InputTest behavior.
