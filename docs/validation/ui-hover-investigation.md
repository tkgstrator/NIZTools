# Hover movement: reproduced source cause and bounded fix

Workspace: `/Users/devonly/Developer/personal/NIZ`, host `devonlys-MacBook-Pro.local`. These probes use the actual App with the in-process DEMO worker and native-order raw_input_hook. No native GUI, device I/O, Git, Simulator, or distributed app mutations were performed by the worker.

The prior frozen source reproducibly moves unselected selectable controls on the first pointer-hover frame. At Light/Dark and 960×820/700×580, swap mode text moves 1 logical point, its control grows 2 points, and following layer labels move 2 points. The calibration tab and right-Fn layer have the same effect. Native pixels per point 2 additionally reproduces actual glyph-mesh and control-paint bounds, so this is not a text-rectangle-only approximation.

Evidence: `hover-jitter-probe.rs/.log`, `hover-jitter-retina-probe.rs/.log`, and the independent parent `hover-jitter-independent-response-probe.rs/.log`. At Retina scale, swap glyph bounds change [[123.5,165],[229,178.5]]→[[124.5,165],[230,178.5]], and the control changes [[114,158],[237.9,184]]→[[114,158],[239.9,184]]. Ordinary buttons, the device/appearance combo buttons, selected chips, and keycaps stay fixed.

Pinned egui 0.36.2 Button::selectable (`widgets/button.rs:78–82`) sets frame_when_inactive(selected). `widget_style.rs:163–167` subtracts the 1-point stroke width from frame inner padding. The unselected Inactive path (`widgets/button.rs:364–367`) drops that stroke while retaining the reduced inner padding. Hover retains the stroke, restoring a point on each side. `containers/frame.rs:327–331` sums inner margin plus stroke width. Both label displacement and neighboring layout movement therefore follow directly from the source allocation.

All WidgetVisuals expansions are zero. The floating scroll style allocates zero width. Tooltip dwell did not create a memory Popup. The movement precedes tooltip opening and happens immediately on hover. Those mechanisms are ruled out for the reproduced symptom.
