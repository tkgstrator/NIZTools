## Concrete plan findings to resolve

- **P2: configure both complete theme styles.** Current app.rs:46-78 forces Light and customizes only the active global style. Installed egui 0.36.2 context.rs:2152-2250 shows ThemePreference::System follows native RawInput.system_theme, while set_global_style only replaces the active theme style. Register customized Light/Dark styles using set_style_of/all_styles_mut, with identical font sizes, spacing, padding and other geometry. Otherwise switching can silently restore stock dark geometry and affect the accepted layout.
- **P2: centralize all foreground/background roles rather than only changing root color.** Current custom colors appear in app.rs:62-77,724,759-800 and keyboard.rs:249-253,280-320. Dark root with white cards/light keycaps, or dark text over dark panels, would leave inconsistent/readability failures. Cover root, card, modal/window, popup/menu, text edit, scrollbar, neutral keycaps, ordinary/secondary text, primary actions, selected tabs/layers, hovered/active/focused widgets, From/To labels/outlines/fills, dirty dots, warnings and errors. Include both strong and weak widget fill variants. Derive theme-specific helpers from the effective visual theme, not directly from the System enum.
- **P2: preserve selected and explicit text colors.** Do not reinstate global override_text_color, which previously overrode white selected-tab text. Define normal and secondary foregrounds, selected foreground/fill, primary-button foreground/fill, and per-key selected text as semantic pairs. Check selected, hovered selected, keyboard-focus and popup-item states, not just a static unselected screen. Meaningful selection and dirty markers remain distinguishable from warning/error.
- **P2: System must update after startup and preserve a user override.** Keep appearance preference separate from resolved theme. System follows later native input theme changes; explicit Light or Dark ignores them. Use egui's observed System pathway, not OS preference writes, a one-time startup sample, shell polling, or an inferred theme from colors. If native theme is unavailable, use a defined framework/app fallback and do not claim the OS theme was detected.
