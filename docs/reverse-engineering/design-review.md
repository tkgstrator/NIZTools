# Atom66 macOS設計のレビュー結果

2026年10月10日、[Rust macOSユーティリティ設計案](../superpowers/specs/2026-10-10-niz-macos-design.md)を2人の独立したCodexエージェントが読み取り専用でレビューした。LocalGPTとClaude Code MCPの呼出手段は確認できず、その代替として行った設計レビュー。実装・コード差分・ハードウェア書込のレビューではない。

両レビュアーは `devonlys-MacBook-Pro.local` と `/Users/devonly/Developer/personal/NIZ` を確認し、設計と元ZIP、DLL解析、固定した公開ソースの証拠を調べた。レビュー依頼時に他のレビュアーの結論を共有しなかった。

## 指摘と修正

| 指摘 | 初回の重要度 | 設計に反映した条件 |
| --- | --- | --- |
| 復元元と現在状態の混同 | P2 | live_baselineとdesired_profileを分ける。再接続でbaseline無効化。版と構造を検証し、3→9 importでは宛先の追加グループを保持 |
| 意味だけの比較では未知バイトの破損を見逃す | P2 | 全グループの未編集レコードは全バイト照合。編集レコードも保持対象を確認。実測した正規化位置だけ例外にする |
| バックアップ保存完了の条件不足 | P2 | 一時ファイルの全write、flush、sync、上書きなしの原子的公開、再解析とハッシュ照合をF1の前提にする |
| 即時readbackだけでは保存と復元を証明できない | P2 | 初回認定で再接続・電源再投入後の読取、USB／Bluetoothの実キー出力、復元後の再確認を行う |
| report間隔とF6後の待機が未定義 | P2 | 公開実装の3ms／300msを仮の初期値とし、実測で調整。時間経過だけで成功にしない |

さらに、hidapiの同期writeではアプリの待ち時間切れが物理送信の取消を意味しないことを明記した。未完了送信と競合するunlockやcloseを行わない。

両レビュアーが修正版を再確認し、それぞれの重要な指摘が設計上解消されたと報告した。残ったP3の「公開を原子的と明記する」表現も修正した。Codexが元ZIPのハッシュ、descriptor、修正したマクロ解析、資料のリンク、設計の受入条件を別途確認した。

## 確認済みの範囲

offline codecと読取専用CLIへ進む設計上の阻害要因は指摘されなかった。設定書込を有効にするには、設計で要求するファームウェア識別、完全なcapture、保存・復元、実キー出力の実機確認が必要。

Rustアプリはまだ実装されていない。設定用HID出力report、ファームウェア更新、校正コマンドは今回送っていない。設計レビューの完了は、任意の不正データに対して実機が故障しないことを保証しない。
