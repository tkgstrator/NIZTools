# NIZ macOS Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development. Steps use checkbox syntax for tracking. The owner already approved proceeding from the reviewed design.

**Goal:** Atom66 EC-BLEの設定をMacで読取・保存・編集するRust GUIとCLIを作り、検証済みの書込手順と両CPU向け配布物を用意する。

**Architecture:** 4 crateのCargo workspace。niz-coreがreportとプロファイルを扱い、niz-deviceがHIDとバックアップ付き適用を所有する。CLIとegui GUIは同じAPIを使い、GUIの機器操作は専用スレッドに送る。

**Tech Stack:** Rust edition 2024、serde／serde_json、thiserror、hidapi 2.6.7、clap 4、eframe 0.36.2（default features無効、glow／default_fonts／x11／wayland／accesskit、Renderer::Glow）、SHA256、quick-xml。日本語フォントはSIL OFL付きNoto Sans JP。

**Spec:** ../specs/2026-10-10-niz-macos-design.md

## Global Constraints

- 対象workspaceは `/Users/devonly/Developer/personal/NIZ`、ホストは `devonlys-MacBook-Pro.local`。元ZIPを変更しない。
- Gitリポジトリではないため、作業場所を移さず現在のプロジェクトに作成する。Git初期化、コミット、pushをしない。
- 内部report64バイト、hidapi送信65バイト、Report ID 0。受信64バイトの先頭を削らない。
- hidapiのmacos-shared-device featureを有効にし、設定collectionへの非exclusiveアクセスを使う。機器の通常入力をOSから奪わない。
- VID0483、PID502a／512a／522a、usage008c／1。F9で66EC系を追加確認し、機能識別にはS BLEを必要とする。
- 最大8192 report、ファイル4MiB、応答待ち1000ms、stream全体30秒。3／9グループ、キー1〜66。
- 未編集レコードと追加グループは全バイト保持。未知構造は診断だけ保存。Fn割当は全編集レイヤーで一致させ、左右Fnを失う編集を拒否する。
- ファームウェア更新、校正、任意raw送信APIを作らない。通常実機操作は初めにF9／F2の読取だけを行う。
- 書込は完全baseline、版／機種／構造の一致、durable backup、全report検証、readbackを必要とする。writeのtimeoutを物理取消とみなさない。
- 初期化や実機設定変更はテストだけで実行しない。実機の書込認定が終わるまでは明示した未認定状態をUIとCLIに示す。
- 原ソフトとファームウェアを配布物に同梱しない。参照コード・フォントのライセンスを残す。

## Review Focus

1. 先頭が0の有効な64バイトreportを受信時に削らない。短いreportと無期限streamは失敗する。
2. 設定B上へバックアップAを復元できる。Aをbaselineにして外部変更検出を壊さない。
3. 3グループimportが9グループbaselineの追加6グループを失わない。版不一致と再接続は拒否する。
4. backup公開・sync・再解析の失敗前にF1を送らない。未編集の不明バイトの変化をreadbackで検出する。
5. 空／重複／欠落のXML・JSONを機器へ送らない。切断時にはオフライン草稿を保持し、別機器へ自動適用しない。

## 共通インターフェース

`niz_core::Report = [u8; 64]`。

`Definition { kind: u8, keys: Vec<u8>, interval: u16, cycles: u8, custom_delay: bool, delays: Vec<u16> }` はClone／Debug／PartialEq。

`DeviceIdentity { vendor_id: u16, product_id: u16, usage_page: u16, usage: u16 }` はClone／Default／serde対応。serialやOS pathはファイルへ入れない。

`Profile { firmware: String, identity: DeviceIdentity, records: Vec<Vec<Report>>, counters: Vec<u32>, captured_at: String }` はClone／Debug。raw reportのJSONはhex文字列で保存する。

coreの公開APIは `command(op: u8) -> Report`、`encode_definition(index: usize, def: &Definition) -> Result<Vec<Report>>`、`decode_definition(reports: &[Report]) -> Result<Definition>`、`key_name(code: u8) -> &'static str`、`parse_key(text: &str) -> Result<u8>`、`KEY_ROWS`、`KEY_WIDTHS`。

Profileは `from_reports(firmware: String, identity: DeviceIdentity, reports: Vec<Report>) -> Result<Self>`、`from_json(text: &str) -> Result<Self>`、`to_json(&self) -> Result<String>`、`demo() -> Self`、`group_count(&self) -> usize`、`reports(&self) -> Vec<Report>`、`definition(&self,index:usize) -> Result<Definition>`、`set_definition(&mut self,index:usize,def:&Definition) -> Result<()>`、`differences(&self,other:&Self) -> Result<Vec<usize>>`、`validate_for_writing(&self) -> Result<()>`、`merge_import(&self,imported:&Self) -> Result<Self>`。

`niz_device::DeviceDescriptor { path: String, product: String, identity: DeviceIdentity }`。`list_devices() -> Result<Vec<DeviceDescriptor>>`、`Session::open(path: &str) -> Result<Session>`、`version(&mut self) -> Result<String>`、`read_profile(&mut self) -> Result<Profile>`、`read_counters(&mut self) -> Result<Vec<u32>>`。

`LiveBaseline`はSessionが発行する不透明な型。privateなsession ID、接続世代、完全読取Profileを持ち、`profile(&self) -> &Profile`のみ公開する。serde対応にしない。`Session::read_baseline(&mut self) -> Result<LiveBaseline>`で発行し、read失敗／切断／partial write後は無効化する。

`save_backup(profile: &Profile, directory: &Path) -> Result<PathBuf>` と `load_profile(path:&Path) -> Result<Profile>` を共用する。`Session::apply(&mut self, baseline:&LiveBaseline, desired:&Profile, backup_directory:&Path) -> Result<ApplyResult>` の結果は `ApplyResult { profile:Profile, backup_path:PathBuf }`。apply内部でsession／世代／last-read一致を確認する。

通常applyはモデル・exact firmware・グループ数・descriptor・変更したアクション機能の認定表でfail closedにする。初期認定表は空。singleが認定されてもcombo／repeat／macroは別認定であり、元baselineの未変更macroだけraw保持して送れる。外部ファイルやCLI flagsでこの表を全面解除しない。

初回の限定試験には `Session::trial_single_key(&mut self, baseline:&LiveBaseline, index:usize, code:u8, backup_directory:&Path) -> Result<ApplyResult>` を別途用意する。現在の単一通常キーを、コード1〜74のFn以外の単一通常キーへ1箇所だけ変更する。元定義もkind0／keys1個、物理位置にFnを含まないことを確認し、全データはlive baselineから作る。この試験は通常のapplyを解除せず、認定表も自動更新しない。CLI `trial-single-key --device PATH --index INDEX --key KEY --confirm-trial` で対象と復元方法を具体的に表示し、親Codexは人からその具体的試験の承諾を得るまで実行しない。

## Task 1 通信codecとプロファイル

**Files:** `Cargo.toml`、`crates/niz-core/Cargo.toml`、`crates/niz-core/src/{lib,error,protocol,profile,keys,legacy}.rs`、`crates/niz-core/tests/`。

**Produces:** 上記core API。Task2と3はこのAPIを使う。

- [ ] Golden reportの失敗テストを先に作る。single／chord先頭は `00f001010002443a`、repeatは `00f00202011234022b2c`。53／54バイトmacro境界と4n／4n−3形式を試す。
- [ ] 3／9グループの完全profile、欠落、重複、変形header、未知kind、サイズ上限、Fn一致、全raw保存、編集以外のbyte保持、3→9mergeを先にテストする。
- [ ] coreを実装する。意味未確認のレコードは変更不可にし、元rawを保持する。macroの新規生成はnative4n形式で末尾delay0を明示するが、実機送信の認定対象に含めない。
- [ ] .proの既知ルートとKEY XMLを取り込む。DTD／entity／不正数値／重複key／欠落key／未知modeを拒否。実Windows標本未取得の限界を残す。
- [ ] `cargo test -p niz-core` を実行し、失敗時点と成功時点をレポートに残す。code品質とspecの独立レビューを受ける。

## Task 2 HID sessionとCLI

**Files:** `crates/niz-device/{Cargo.toml,src/lib.rs,src/transport.rs,src/session.rs,src/backup.rs,tests/}`、`crates/niz-cli/{Cargo.toml,src/main.rs,tests/}`。

**Consumes:** Task1 core API。**Produces:** 共通device APIと `niz` バイナリ。

- [ ] fake transportを使い、短いread、欠落F6、版不一致、遅延report、send失敗、正しい64／65framingのテストを先に失敗させる。
- [ ] VID／PIDとusageで列挙し、pathを指定して開く。descriptorも検証。F9、F2、E3以外の永続変更コマンドをread操作へ含めない。多候補時に暗黙選択しない。
- [ ] Sessionとbackupを実装。Sessionはsingle owner、エラー後の再利用不可。設定streamはraw diagnosticを残す。counter失敗をprofile全体の成功と混同しない。
- [ ] durable backupの原子的公開と再解析gate、restore A over B、外部変更、未編集byte不一致をテスト。apply実装はF1→全F0→F6→300ms→F2を直列実行し、3ms間隔を仮値にする。失敗時に全再送や復旧書込をしない。
- [ ] 別Sessionと旧接続世代のbaselineを同じバイト列でも拒否する。single認定だけでは変更macro／comboを拒否し、未変更macroを保持する。限定trialへmulti-key／Fn／macroの変更を渡せないことを試す。
- [ ] CLIはdevices、info、backup、inspect、diff、set、import、apply、restore、限定trial-single-keyを用意。通常は読取とoffline操作。apply／restoreは具体的差分と未認定状態の明示を必要とし、未認定の変更アクションに書込を許可しない。
- [ ] `cargo test -p niz-device -p niz-cli`。親Codexが `niz devices`、`niz info`、`niz backup` を実機で実行し、logとJSONを保存する。実機writeを委任しない。

## Task 3 デスクトップGUI

**Files:** `crates/niz-gui/{Cargo.toml,src/main.rs,src/app.rs,src/worker.rs,src/editor.rs,tests/}`、`assets/fonts/`。

**Consumes:** coreとdevice API。**Produces:** `niz-gui` バイナリ。

- [ ] editor状態テストを先に作る。layerとkeyのindex、dirty状態、import merge、undo／redo、切断時草稿保持、違うbaselineへの適用防止を検証。
- [ ] 日本語フォントを同梱する。device選択、version、readとbackup、66キー実配置、通常／右Fn／左Fn、単一キー／組合せ／macroのoffline編集、JSON保存／.pro importを実装。
- [ ] 通信workerは専用threadでSessionを所有し、UIとの間をchannelで結ぶ。read／apply中は重複機器操作を防ぎ、同期write未完了を画面だけで取消済みとしない。
- [ ] write画面は変更前後とバックアップ先を示す。未認定firmwareは書込不可を明示。不要なraw commandやcalibration入口は作らない。
- [ ] `cargo test -p niz-gui`、親Codexによる実UI操作とスクリーンショット検証。テストで開いたウィンドウ／プロセスのみ終了。
