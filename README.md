# NIZ Tools

Atom66 の設定を macOS で読み込み、キー割り当てを編集する Rust 製のユーティリティです。Apple Silicon と Intel を含む Universal2 アプリを生成します。キー単位の入力しきい値変更は、現在のアプリでは未対応です。

現在の実機で確認した対象は USB 接続の `66EC-XRGB`、VID `0483` / PID `502a`、ファームウェア `66EC(XRGB)BLe;V1.0.48;V1.0;` です。製品名が Atom66 EC-BLE でも、RGB の有無やファームウェアが異なる機種には書き込みを許可しません。Bluetooth 経由の設定通信は未確認です。

## アプリを使う

ビルド後の `dist/NIZ Utility.app` を開き、接続したキーボードを選んで「読み込む」を押します。起動時の一覧取得と設定の読み込みでは、設定変更コマンドを送りません。

- **キー割り当て**: 設定欄の下にある66キーの配列をクリックすると、From と To にそのキーの現在の設定が入ります。To で新しい出力を選び、「変更を追加」で草稿に反映します。通常は片方向の割り当て変更です。「2つの位置を交換」では From、To の順に配列をクリックして交換する位置を選びます。クリックだけでは変更や実機への適用は行いません。
- **草稿**: 変更はまずアプリ内に保持されます。元に戻す・やり直す、JSON 保存、JSON / `.pro` の読み込みに対応します。ファイルを開いただけでは実機に適用されません。
- **実験的な適用**: 上記の実機と同じ構成について、基本キー1つの変更または2つの交換だけを許可します。変更前に設定と照明を保存し、変更後に両方を読み直して比較します。既定の保存先は `~/Library/Application Support/NIZTools/Backups` です。複数の編集、Fn のある位置、特殊機能、未対応データの変更は拒否します。
- **入力しきい値**: 「しきい値を読み込む」で通常スキャンの内部しきい値を取得し、下の配列で選んだ物理キーの値を10進数と16進数で表示します。キー選択だけでは通信しません。選んだキーだけのしきい値変更は未対応と表示し、設定変更を実行しません。全体のしきい値切替や全キー校正を、個別調整として実行する操作は置きません。
- **入力テスト**: アプリに届いた文字と押下中のキーを確認し、読み込み済みの割り当てに一致する配列の位置を点灯します。未適用の草稿は点灯の照合に使いません。テスト中のキー入力では画面のボタンを操作せず、マウスで別の画面へ戻れます。

配列の緑は From、金色は交換先の To、オレンジの点は未適用の変更です。通常・右 Fn・左 Fn の各レイヤーに切り替えられます。上部の外観から「システム」「ライト」「ダーク」を選べます。既定のウィンドウでは主要操作と配列が収まり、小さいウィンドウや詳細を展開した状態では縦にスクロールできます。

From の位置番号はレイヤー内で固定です。配列の形と位置番号は公式 Windows ソフトの静的解析を基準とし、ボタンには現在の草稿の割り当てを表示します。印字と同じとは限りません。刻印は選択欄とツールチップで確認できます。未対応の機能は元データを保持し、明示的に新しい出力を選ぶまで置き換えません。

入力テストは macOS がこのアプリへ届けた入力を使います。入力元のキーボードや元の物理スイッチは特定できず、同じ出力を複数の位置に割り当てた場合は候補をすべて点灯します。Fn レイヤーは照合の基準を手動で選びます。Fn、Caps Lock、OS が処理するショートカットなど、受け取れない入力もあります。未読み込み・通信断・再読み込みが必要な状態では割り当てとの照合を止めます。文字列は最大256文字をアプリ内だけに保持し、貼り付け・自動保存・ログへの出力は行いません。

### キー単位の入力しきい値について

要求する操作は「選択した物理キーだけの入力しきい値を変更し、他の65キーを保持すること」です。現在の `66EC(XRGB)BLe;V1.0.48;V1.0;` の通常の HID コマンド処理を静的解析した範囲では、それを行うキー指定・数値指定の書き込みコマンドを確認できていません。アプリは推測した数値や mm 値を表示せず、キーを選んだだけで設定を変更しません。

既存の校正開始コマンドは66キーすべての基準値を更新します。押した状態の校正も、選択したキー番号ではなく、全キーのアナログ値に対する条件で変更対象を決めます。そのため、この校正をキー単位のしきい値変更として提供できません。全体説明と校正の開始・続行操作を、入力しきい値の画面から外しました。

通常スキャンのしきい値テーブル R は、上記の実機から読み取りを確認しました。GUI の「しきい値を読み込む」と CLI の `raw-thresholds` は、正確な識別情報と最新のファームウェアを確認してから DC mode 1 を1回だけ要求します。66キーすべての値と11フレームを取得し、物理キーの配列へ変換します。2026年10月11日の2回の取得では全データが一致し、A（#31）は23 / `0x17`、S（#32）は25 / `0x19` でした。[実機の生値取得記録](docs/validation/2026-10-11-raw-thresholds-hardware.md)に受信データと検証範囲を保存しています。

この値の単位はファームウェア内部の信号値です。押し込み量の mm、現在のセンサー値、すべてのスキャンモードの判定値を示すものではありません。表示は取得時点のスナップショットで、連続更新しません。キーを離して取得してください。取得中は入力スキャンが一時停止し、動作中の補正値は以前の値ではなく設定された既定値へ戻ります。永続設定を変更するコマンドは送りませんが、動作状態への影響はあります。失敗時の待機もスキャン復帰の確認にはならず、再接続・再読み込みを必要とする状態へ移行します。

生値を読めることは、個別の書き込みや復元ができる根拠にはなりません。[正確なファームウェアの調査記録](docs/validation/per-key-firmware-evidence.md)に、判明した処理と未確認の範囲を記録します。

校正の内部実装と模擬通信テストは保持しています。設定と照明のバックアップにはアナログ校正値が含まれず、校正値の復元機能はありません。以前から進行中の校正を処理する場合は中止と終了処理を待つ表示を残し、ロック解除の「送信済み」を入力回復の確認として扱いません。

## 開発とビルド

Rust **1.95 以上**と macOS の Command Line Tools が必要です。開発時に使った Rust は1.98.1です。

```sh
cargo test --locked --workspace --all-targets
cargo fmt --all -- --check
cargo clippy --locked --workspace --all-targets -- -D warnings
cargo run --locked -p niz-gui -- --demo
```

`--demo` は実際の HID デバイスを開かない模擬動作です。デモの成功を実機の成功として扱いません。

```sh
rustup target add aarch64-apple-darwin x86_64-apple-darwin
./scripts/build-macos.sh
```

生成物は `dist/NIZ Utility.app`、`dist/NIZ-Utility-universal.zip`、Universal2 CLI `dist/niz` です。最低 macOS バージョンは13.0です。ローカルの ad hoc 署名を付けます。Developer ID 署名や公証は含みません。Intel 向けビルドは Intel 実機での HID 動作を保証するものではありません。

## CLI

CLI は設定取得、バックアップ、差分確認とオフライン編集に対応します。

```sh
cargo run --locked -p niz-cli -- devices --json
cargo run --locked -p niz-cli -- info --json
cargo run --locked -p niz-cli -- raw-thresholds --json
cargo run --locked -p niz-cli -- backup --directory ./backups
cargo run --locked -p niz-cli -- inspect ./backups/settings.json --json
cargo run --locked -p niz-cli -- swap ./backups/settings.json --from-index 30 --to-index 31 --output ./draft.json
```

CLI のインデックスは **0始まり**で、通常レイヤーは0–65、右 Fn は66–131、左 Fn は132–197です。GUI のレイヤー内位置番号は1始まりです。バックアップの実際のファイル名を `inspect` や `swap` に渡してください。

`raw-thresholds` の JSON の `values_by_physical_position` は公式配列の物理位置順で、配列の先頭が GUI の #01 です。受信した11フレーム、対象、ファームウェア、単位、取得に伴う動作状態への影響も出力します。`--device` で接続先を指定でき、失敗時は `--capture ./failed-read.json` に通信記録を保存できます。アプリが同じ接続先を使用中の場合は、アプリを終了してから CLI を使います。

`apply` / `restore` の通常書き込み資格表は現在空で、未認定の操作を拒否します。明示的な `trial-single-key` / `trial-swap --confirm-trial` は GUI と同じ限定した試験用です。個別のしきい値変更や校正を開始する CLI 操作は提供しません。ファームウェア書き換え、任意の生コマンド送信、照明の書き込みは実装していません。
